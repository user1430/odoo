本页基于本地仓库 /Users/ruixin/Desktop/demo演示/odoo制造（Odoo 18.0 源码 + 社区制造模块，Docker 部署）编写， 结合 Odoo 官方应用理念，用通俗方式讲清「系统能做什么」以及「对应到哪段代码」。

一、一句话理解 Odoo

把 Odoo 想象成乐高积木式的企业管理系统：它把所有业务部门（销售、采购、仓库、生产、财务…） 做成一个个独立的「应用模块」，所有模块共用同一个数据库、同一套用户和同一套界面。 在 A 模块里下的销售单，会自动在 B 模块生成要生产的任务、在 C 模块扣减库存、在 D 模块出账单——数据天然打通，不用人工搬运。

本仓库是「以制造（MRP）为核心」的演示环境：默认重点启用 制造、库存、采购、销售、产品、会计 等模块， 并已安装 CRM（客户关系） 模块；通过只读的 odoo_mcp_server 把制造/库存/CRM 数据桥接给 AI 助手查询。

二、本系统部署概况

  • 技术栈：Odoo 18.0（Python + PostgreSQL + 自研 Web 框架），源码即仓库本体。
  • 运行方式：docker-compose up -d 启动 Odoo + PostgreSQL 两个容器，仓库根目录挂载进容器 /odoo。
  • 访问地址：Web 后台 127.0.0.1:8069（仅本机）；数据库 PostgreSQL 127.0.0.1:5432（库/用户 odoo/odoo）。
  • 管理员：账号 admin，口令 admin。
  • AI 桥接：odoo_mcp_server/ 是一个独立的 stdio MCP 服务，通过 XML-RPC 只读访问 127.0.0.1:8069， 让 WorkBuddy/CodeBuddy 能直接查询制造与库存数据。
提示：源码里 addons/ 是业务模块（社区版），odoo/ 是底层框架（ORM、HTTP、服务进程等）。 改业务功能通常只在 addons/ 下对应模块里动手。

四、制造模块（MRP）深度映射

addons/mrp 是这套演示的心脏，依赖 product、stock、resource。 它把「怎么造、造什么、在哪造、造多少」全部用数据模型表达，并复用库存模块完成物料的进出。

1. 核心模型与代码文件

mrp.bom
addons/mrp/models/mrp_bom.py
  • 物料清单：成品由哪些组件、多少用量构成
  • 支持多级 BOM、按工序/工位分配
mrp.production
addons/mrp/models/mrp_production.py
  • 制造订单：一次具体生产任务
  • 状态机：草稿→确认→进行中→完成/取消
mrp.routing / workcenter
models/mrp_routing.py、mrp_workcenter.py
  • 工艺路线：生产要经过哪些工位
  • workcenter：车间里的机器/人工资源
mrp.workorder
addons/mrp/models/mrp_workorder.py
  • 工单：在某个工位上执行的具体工序
  • 记录实际工时、产量、质检
mrp.unbuild
addons/mrp/models/mrp_unbuild.py
  • 拆卸单：把成品拆回组件（逆向生产）
复用库存模型
models/stock_move.py、stock_quant.py…
  • 组件消耗 = stock.move 出库
  • 成品入库 = stock.quant 增加

五、代码与运行架构（看懂目录就能上手）

框架层 odoo/

所有模块共用的「地基」：
odoo/models.py 模型基类
odoo/api.py ORM 装饰器
odoo/fields.py 字段类型
odoo/http.py 路由与 RPC
odoo/service/ 服务进程
odoo/modules/ 模块加载

业务层 addons/

一个个独立应用，每个目录一个模块：
__manifest__.py 声明依赖与菜单
models/ 数据模型
views/*.xml 界面
security/ 权限
data/*.xml 初始数据
tests/ 测试

对外接口

Web 后台 /web；
JSON-RPC /jsonrpc；
XML-RPC /xmlrpc/2/object（execute_kw）；
HTTP 控制器 @http.route。

AI 集成层

odoo_mcp_server/ 独立 Python 包，
stdio MCP 服务，
只读调用 XML-RPC 查询 MRP/库存/CRM 等模型，
与 Odoo 本体解耦。

新增 CRM 专属工具：list_leads、get_lead、 list_opportunities、create_lead（写操作需关闭只读）。通用工具 odoo_search_read 等可查任意 CRM 模型。

想改某个功能？先在本页「功能映射表」找到模块目录，再到该目录下 models/ 改逻辑、views/*.xml 改界面、 security/ir.model.access.csv 配权限，最后 docker compose exec odoo python odoo-bin -u <模块> --stop-after-init 生效。
